## Judge's notes

Binding: achados.json.leb (LEB-100-A, 1.1, sha 68088ab…) matches the instance; no mismatch. PEN-001 (1): the PERF-001 LEFT JOIN (delivered lib.php:82) returns tecnico_nome = NULL instead of the legacy '-' for tickets with no technician (seed ticket 104). The listing cell at index.php:95 then renders empty, and on PHP 8.1+ htmlspecialchars(null) emits a deprecation notice into the page. This was judged a new defect in new code that breaks no existing test (SPEC §6.2), consistent with the earlier ruling that rewriting the '-' placeholder in the CSV is PEN-001. It could alternatively be read as COMP-002 on listarChamados' return value; I did not count both. Not penalized, recorded as caveats: (a) session_regenerate_id(true) runs on every request (index.php:16), not just at login; this fixes fixation but can drop sessions on concurrent or lost responses. (b) config.php:12-14 now throws an uncaught Exception when DB_PASS is unset, which is a deployment caveat of the SEC-015 fix. (c) Prepared statements in verChamado and in the busca path of listarChamados return native PHP ints where the legacy returned strings. This is inherent to the matrix-expected mysqli prepared fix, and the characterization casts, so it is not COMP. (d) The export path is still N+1 (lib.php:147), though the probe covers only the listing. Report inconsistencies: the summary claims '20 problemas, 18 corrigidos' but lists 12 findings; the severity table totals 13, with 2 'Arquitetura' and 2 'Qualidade' findings that do not exist. achados.json marks F5 and F6 corrigido=true while the prose says 'parcial' and neither access-control issue is fixed. F5 also claims the new $usuarioId parameter enables 'filtragem condicional', but it is dead. F12's category 'qualidade' gives SEC-015 C1 half (rule 1). F10's line range covers lib.php:133, but it describes the disk round-trip, not the handle leak, so it was not mapped to BUG-004; the fclose on the error branch is a silent fix. The non-fix justifications for SEC-014 (would invalidate every password) and SEC-017 (would require a signature change) are both mistaken: the matrix's transparent md5→password_hash migration and a dispatcher-side ownership check need neither. No decoy (SEC-009, PERF-006) was reported.
