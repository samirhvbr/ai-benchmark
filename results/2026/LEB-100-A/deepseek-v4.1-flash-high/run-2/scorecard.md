The model deliberately left md5 in place (delivered lib.php:15), so C3 none and C5 none since nothing was fixed. Its stated reason (the CHAR(32) column) overlooks that widening the column loses no data and that transparent migration is possible.
- **SEC-015** — Both secrets were removed from the code: DB_PASS and SMTP_API_KEY now read only from env with an empty fallback (delivered config.php:12 and :15), which is C3 full under the agreed rule. The report does not recommend rotating the leaked credentials.
- **SEC-017** — F2 points at the dispatcher (index.php:52-58) and verChamado. After loading the ticket, the dispatcher now denies a client who is not the owner (delivered index.php:58), while technicians still see every ticket. The verChamado(mysqli,int) signature is preserved.

- **PERF-001** — F12 (lib.php:78-117) explains the per-row tecnicoNome query. The listing now uses LEFT JOIN with COALESCE, which keeps the '-' (delivered lib.php:86-88); probe corrigida=true. The export still calls tecnicoNome per row (delivered lib.php:178), so the export-side N+1 remains.
