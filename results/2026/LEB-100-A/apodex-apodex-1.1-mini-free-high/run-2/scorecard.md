## False positives and findings outside the matrix

- F3 - SQL injection in tecnicoNome (code/lib.php:70) — not a real issue, confidence 90. tecnicoNome is declared tecnicoNome(mysqli $db, ?int $tecnicoId): the argument is typed, against the report's premise that 'a própria função não tipa o argumento', and every caller casts with (int). Only an integer or null can reach the concatenation, so no caller can inject. It claims exploitability ('Um caller malicioso ou bugado injeta') and does not present it as a latent pattern that is safe today, so it is a false positive, not an extra (digest A10). It is not a matrix decoy.
- F4 - SQL injection in verChamado (code/lib.php:100) — not a real issue, confidence 90. verChamado(mysqli $db, int $id) only accepts an int. The report credits the mitigation to the caller's (int) but asserts that 'a função pública continua vulnerável a outros consumidores', which the function's own int type declaration rules out. It claims a real vulnerability rather than a latent pattern admitted safe, so it is a false positive (digest A10; U is the contrasting extra case). It is not a matrix decoy.
