For an unknown login it runs password_verify against a cost-12 bcrypt dummy (delivered lib.php:30-33, ~175 ms measured on PHP 8.4). For an existing account still on a legacy md5 hash, a wrong password is rejected via md5+hash_equals in microseconds (lib.php:37-40). That covers every seeded user before first login, and every user on an existing CHAR(32) database. The legacy code did one identical SQL query in both cases. The report's claim that the dummy hash equalizes timing ('275 ms contra 280 ms') holds only for already-migrated bcrypt accounts. PEN-003=0: the system was evolved in place, not rewritten.
